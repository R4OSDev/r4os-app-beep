# BEEP.R4X

`BEEP.R4X` is an independent R4OS application implemented in Zig.

## Package

- Version: `0.1.9`
- Image target: `/R4OS/SOFTWARE/TERMINAL/BEEP.R4X`
- Image scope: `full`
- Canonical project manifest: `module.R4MF`

The manifest is the single source of truth for the artifact, imports, image
target, and package metadata.

PCM pacing uses absolute R4SYS tick deadlines from each real write attempt.
Source work, synchronous writes, Busy and scheduling time consume that budget.
The 160-ms source lead remains; the final wait covers only the remaining host
budget and is followed by the actual owned stream Close. These deadlines do
not acknowledge device playback. Missing ticks/sleep or an unknown frequency
fail before opening PCM; no assumed frequency replaces them.

`./Build.sh test` (Windows: `Build.bat test`) exercises the actual application
and SDK with controlled time, exact unchanged PCM, partial writes/Busy, missing
time support and real Close results. `Tests/Guest/Playback/Build.ps1` builds an
explicit private SMP4/HDA process observer, excluded from normal images. It
requires the installed BEEP/SYNTH apps, AUDSVC, HDA and the three documented
PCM57/CVT57/LONG57 WAV fixtures in `C:\TEMP` (generated by the adjacent
`MakeInputs.ps1`); modes B/N/W/C/S/P/Q select the
short/full tone, direct/converted WAV, short selftest, Pause/Resume or Quit.
It records accepted source bytes and exact owned child completion/full output/
reap/release, actual output Idle and resource cleanup. Per-stream consumed
frames remain unavailable to this external observer; see `Docs/Audio/README.txt`
in the coordinating workspace for immutable runtime evidence and fixture hashes.

## Build

On Windows:

    Build.bat

On Linux or macOS:

    ./Build.sh

The build starters resolve the current local R4OS dependency checkouts through
`Settings.R4S`. The URL and hash entries in `build.zig.zon` record the
last verified standalone dependency identities; workspace builds use the
mapped local checkouts.
